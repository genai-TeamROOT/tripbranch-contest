## 1. 질문

**폴백 모델로 떨어졌을 때 인텐트 분류 품질이 유지되는가.**

1순위 모델이 실패하면 사용자가 실제로 받는 답은 이 모델이 낸다. 그런데 품질을 잰 적이 없다.

폴백 체인(D-052)은 2026-08-11까지 동작하지 않았다. `.env`의 폴백 모델명이
`gemini-2.0-flash-lite`였는데 이 API 키의 모델 목록에 없어 `404 NOT_FOUND`였고,
404는 비재시도 오류라 폴백 없이 즉시 실패했다. `gemini-2.5-flash-lite`로 교체한 뒤
968ms 정상 응답 1건을 확인한 것이 현재까지의 전부다.

**즉 폴백 경로는 이제 막 살아난 상태이고, 그 경로의 품질은 미검증이다.**

## 2. 왜 정확도를 "변수"가 아니라 "가드"로 쓰는가

이 저장소의 분류 정확도는 이미 천장에 닿아 있다.

| 세트 | 결과 |
|---|---|
| 인텐트 68건 (채점 대상 64건 기준) | 63/64 = 98.4% — thinking 예산 3안 전부 동일 |
| 혼잡도 26건 | 26/26 = 100% |

무엇을 바꿔도 위로는 움직이지 않는다. 따라서 이 실험의 정확도 지표는 **개선을 재는 눈금이
아니라 하락을 잡는 감지기**다. 판정 기준(§5)도 "얼마나 좋아졌나"가 아니라 "깨졌는가"로 쓴다.

## 3. 통제 변수

| 항목 | 값 | 이유 |
|---|---|---|
| **변수** | **모델명 1개** | 이것만 바꾼다 |
| thinking | 양쪽 `--budget 0` 고정 | 두 모델의 thinking 기본값이 다를 수 있다. 명시적으로 못 박아 교란을 없앤다 |
| 프롬프트·응답 스키마 | 고정 | `build_intent_classification_instruction()` 그대로 |
| temperature | `0.0` | `app/providers/gemini.py:465` |
| 케이스 | 68건 전수 | `../intent_cot_2026-08-11/intent_classification_cases_2026-08-11.csv` |
| 폴백 체인 | **비활성** | 러너가 `model_names=[단일]`로 넘긴다. 폴백이 끼면 어느 모델의 답인지 알 수 없어 비교가 무의미해진다 |
| 측정 범위 | `classify_intent()` 1단계만 | 서버·라우트·2단계 추출 제외 |

## 4. 실행 절차

작업 디렉터리는 `backend/`. 아래 `$OUT`은 이 실험 폴더를 가리킨다.

```bash
OUT=test_results/fallback_model_ab_2026-08-12
```

`--out-dir`를 빠뜨리면 결과가 CoT 실험 폴더(`intent_cot_2026-08-11/`)로 떨어진다 —
러너의 기본값이 그쪽이다.

### 0단계 — 재현성 확인 (대조군)

```bash
python -m scripts.measure_intent_thinking --budget 0 --model gemini-2.5-flash \
  --repeat 1 --delay 1.0 --tag flash_b0 --out-dir $OUT
```

2026-08-11의 `budget=0` 결과(채점 대상 64건 중 63건, 유일 오답 68번 "어디가 좋아?")를
재현하는지 확인한다.

**재현되지 않으면 실험군을 돌리지 않고 중단한다.** 모델 내부 스냅샷이 하루 사이 움직였다는
뜻이고, 그 경우 lite와의 차이가 모델 차이인지 시점 차이인지 구분할 수 없다. 스냅샷 버전을
고정할 수단이 없다는 것은 선행 실험 §6에 이미 기록된 한계다.

대조군 수치는 2026-08-11 파일을 재사용하지 않고 새로 뽑는다 — 두 안의 측정 시점을 맞춰야
API 쪽 조건 변동이 상쇄된다.

### 1단계 — 실험군

```bash
python -m scripts.measure_intent_thinking --budget 0 --model gemini-2.5-flash-lite \
  --repeat 1 --delay 1.0 --tag lite_b0 --out-dir $OUT
```

0단계 직후 연달아 실행해 두 안 사이의 시간 간격을 최소화한다.

### 2단계 — 판정이 갈린 케이스만 반복

두 안의 예측이 다른 케이스 번호를 모아 각각 5회씩 재측정한다.

```bash
python -m scripts.measure_intent_thinking --budget 0 --model gemini-2.5-flash-lite \
  --repeat 5 --only <갈린 번호들> --tag lite_b0_repeat --out-dir $OUT

python -m scripts.measure_intent_thinking --budget 0 --model gemini-2.5-flash \
  --repeat 5 --only <같은 번호들> --tag flash_b0_repeat --out-dir $OUT
```

**1회 측정의 차이는 노이즈와 구분되지 않는다.** 선행 실험에서 `budget=512`의 오답이 5/5로
동일하게 재현되어 노이즈가 아님이 드러난 것과 같은 방식이다.

## 5. 판정 기준 (실행 전 확정)

결과를 본 뒤에 기준을 정하면 실험이 아니라 사후 해석이 된다. 모수는 **채점 대상 64건**
(19·50·60·31 제외 — 규칙이 없거나 기대값이 미정인 케이스, 선행 실험과 동일 규약).

| 결과 | 판정 |
|---|---|
| 하락 0~1건이고 재측정 5회에서 재현되지 않음 | **채택** — 폴백이 안전망으로 작동한다 |
| 하락 2~3건이고 특정 intent 그룹 쏠림 없음 | **조건부 채택** — 폴백은 유지하되 한계를 문서화한다 |
| 하락 4건 이상 | **기각** |
| MODIFY·RECOMMEND·SCHEDULE에서 5/5로 재현되는 오답 | **건수와 무관하게 기각** |

마지막 줄이 핵심이다. 이 세 그룹이 64건 중 40건으로 실사용 경로의 대부분을 차지한다.
총점이 유지되어도 여기서 재현되는 오답이 하나라도 나오면 폴백으로 쓸 수 없다.

**지연도 함께 본다.** lite가 flash보다 느리면 폴백 시 10초 타임아웃 위험이 되살아난다 —
선행 실험에서 504를 2건 만든 것이 정확히 그 경로다.

## 6. 측정하지 않는 것

| 제외 | 이유 |
|---|---|
| 토큰 | 러너가 `usage_metadata`를 수집하지 않는다. 넣으려면 코드 수정이 필요한데, 프롬프트가 동일해 토큰 수도 같을 것이고 비용 차이는 단가로 계산하면 된다 |
| 2단계 조건 추출 | 러너는 1단계 분류만 본다. 폴백 모델의 추출 품질은 별개 과제이고, 보려면 서버를 띄우는 도구가 따로 필요하다 |
| 실제 폴백 전환 동작 | 이 실험은 "전환됐을 때의 품질"만 본다. "언제 전환되는가"는 D-052 체인의 문제로 별건이다 |

## 7. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| lite가 `thinking_config`를 거부 | 즉시 오류로 드러난다. lite만 `--budget`을 생략해 재실행하되 **thinking 조건이 갈렸다는 교란을 결과에 명시**한다 |
| `429` (lite의 쿼터가 다를 수 있음) | `--delay`를 2.0으로 올려 재실행. 러너가 케이스별로 오류를 기록하므로 어디서 끊겼는지 남는다 |
| 0단계 재현 실패 | 실험 중단. 원인 규명이 우선이며, 스냅샷 드리프트라면 선행 실험 결론의 유효기간 문제라 그 자체가 더 큰 발견이다 |

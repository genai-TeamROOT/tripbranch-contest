# 합성 리뷰 생성 모델 비교 (2026-08-25)

Gemini를 오픈 모델로 대체할 수 있는지 재고 그 근거를 남긴다(TP-151).

## 결론

`gemini-3.5-flash-lite`로 확정했다. 통과율 2배 이상, 속도 10배 이상 차이가 나서
오픈 모델로 대체할 근거가 없었다.

| 모델 | 통과율 | 장소당 소요 | 처리량 | 종로구 841곳 환산 | 10곳 비용 |
| --- | --- | --- | --- | --- | --- |
| **gemini-3.5-flash-lite** | **90%** (9/10) | 4.4초 | 270 tok/s | 1.0시간 | 51원 |
| `qwen3:8b` (Colab T4 + Ollama) | 40% (4/10) | 46.5초 | 18 tok/s | 10.9시간 | 0원 |
| `EXAONE-3.5-7.8B-Instruct` | 0% (0/9) | 44.2초 | 23 tok/s | 10.3시간 | 0원 |

EXAONE은 마지막 장소 결과가 전송 중 잘려 9곳 기준이다.

Gemini 실측 비용은 장소당 5.1원이다. 종로구 전량 약 4,300원, 4개 구 약 1만 3천원,
25개 구(1만 2천~1만 6천 곳 추정) 약 7만원이다. Batch API를 쓰면 절반이 된다.

## 채점 기준

`app.synthetic_reviews.validate_review_batch()`를 그대로 쓴다. 이 함수는 특정 모델에
결합돼 있지 않아 어떤 모델 결과든 같은 잣대로 잰다.

**통과율은 "사실을 지어내지 않았는가"의 측정이다.** 공식 원문 인용의 정확성, 없는 수치
생성 여부, 허용된 근거 필드 사용, 문장 수를 본다. **읽을 만한가, RAG 검색에 걸리는가는
재지 않는다** — 익선동 한옥거리는 통과했지만 리뷰 셋이 "위치를 확인했다"의 변주뿐이다.

## 오픈 모델의 실패 유형

**`qwen3:8b` (6건)**

1. 없는 수치 생성 (3건) — `"09:00~18:00"`을 `"오전 9시부터 오후 6시까지"`로 옮기며
   공식 입력에 없는 `6`과 `9`를 만들었다. 있지도 않은 `"지하철 5호선 삼청역"`도 지어냈다
2. 허용되지 않은 sourceField (2건) — 근거 없는 장소에서 `title`과 `address`를 인용
3. 문장 수 위반 (1건)

검증에 안 걸린 의미 오류도 있다. 금용문의 `"11:30~22:00"`을 **"오후 11시 30분부터
자정까지"**로 읽었다(오전 11시 반부터 밤 10시가 맞다).

**`EXAONE-3.5-7.8B` (9건 전부)**

한국어 문장 자체는 가장 자연스러웠으나 형식 규칙을 거의 지키지 않았다.

1. 문장 수 위반 (5건) — 배열 항목 하나에 문장을 2~3개씩 넣었다
2. 빈 claims (2건) — 스키마에 `minItems: 1`이 걸려 있는데 `[]`를 돌려줬다.
   `qwen3`는 같은 스키마를 지켰다
3. 사실 왜곡 — 공식값이 `"없음"`인 카드 결제를 본문에 "가능합니다"로 뒤집어 썼다

## 실행 환경에서 확인한 것

- **vLLM 최신판은 T4(sm_75)에서 동작하지 않는다.** CUTLASS DSL이 compute capability를
  읽지 못해 모델 로드에서 깨진다. T4가 무료 Colab 기본 GPU라 자주 걸린다.
  Ollama(llama.cpp 기반)로 우회했다
- **Ollama 기본 컨텍스트가 부족하다.** `num_ctx`를 8192로 명시하지 않으면 입력(약
  2,700토큰)이 조용히 잘린다
- 위 측정은 순차 처리 기준이다. `OLLAMA_NUM_PARALLEL`로 동시 요청을 걸면 3~5배
  빨라질 여지가 있다

## 재현 방법

```bash
cd backend

# 1. 표본을 뽑는다. 비교하려면 같은 content_id를 쓴다
python -m scripts.export_synthetic_review_sample \
    --out test_results/<새 폴더>/places_sample__prompt-<버전>.json \
    --place-id 1019041 --place-id 129760  --place-id 1018469 \
    --place-id 1101088 --place-id 1914920 --place-id 1013527 \
    --place-id 2544579 --place-id 2946228 --place-id 3085026 --place-id 629742

# 2. Gemini로 생성한다 (.env에 LLM_API_KEY 필요, 10곳에 약 51원)
python -m scripts.generate_synthetic_review_samples \
    --sample  test_results/<새 폴더>/places_sample__prompt-<버전>.json \
    --out     test_results/<새 폴더>/reviews__gemini__prompt-<버전>.jsonl

# 3. 채점한다
python -m scripts.score_synthetic_reviews \
    --sample  test_results/<새 폴더>/places_sample__prompt-<버전>.json \
    --results test_results/<새 폴더>/reviews__gemini__prompt-<버전>.jsonl
```

오픈 모델은 Colab에서 Ollama로 돌렸다. `places_sample__*.json` 하나만 업로드하면
되고 Supabase 자격증명은 필요 없다 — 표본 파일에 시스템 지시문, 장소별 응답 스키마,
프롬프트 payload가 모두 들어 있다.

**표본 파일 이름에 프롬프트 버전을 붙인다.** 덮어쓰면 그 버전으로 만든 옛 결과를 다시
채점할 수 없다. 리뷰 수가 프롬프트 버전에 따라 달라지기 때문이다(2.0.0은 5개 고정,
2.1.0은 3~5개 가변).

## 측정 중 발견해 따로 고친 것

- **NFC/NFD 정규화 결함** — Gemini가 조합형 한글로 `sourceValue`를 돌려주면 원문과
  다르다고 판정돼, 정확히 베낀 claim이 실패로 잡혔다. generator 3.1.0에서 고쳤다
- **모델이 한글을 뭉개는 문제** — Gemini가 claim 121건 중 11건(9%)에서 글자를
  깨뜨렸다(`게`→`겎`, `연중무휴`→`연쥬므휴`). 사용자에게 보이는 `reviewSentences`에는
  나타나지 않고 `claims[].text`에만 있었다. 검증기가 못 잡는 종류다(TP-153)

## 남은 한계

생성된 리뷰는 **취향 질의 검색에 잘 걸리지 않는다.** 문장 152개 중 114개(75%)가
"확인 / 살펴보 / 고려 / 일정 / 계획"류를 담고 있고 어휘 다양성(TTR)이 0.434다.
`search_place_evidence`가 `taste_query` 임베딩과 유사도 0.43 이상을 요구하는데,
공식 사실 위주 문장으로는 취향 표현과 매칭되기 어렵다.

이는 프롬프트가 방문 경험을 금지하기 때문이고, 그 금지는 사실 날조를 막으려는
의도적 설계다. **RAG가 취향 축을 검색해야 하는지가 정해져야** 다음 방향이 잡힌다.

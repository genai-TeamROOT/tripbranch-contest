## 2. 판정 — 통과. 근거는 흔들림이 아니라 불일치다

### 통과 근거 셋

**① 기대 불일치가 세 번 다 정확히 9/18이다.** 이것이 가장 강한 재현이다.

**③ 발화 단위로도 재현된다.** 세 실행에서 불일치한 발화를 교집합하면 **5건이 3/3으로

### ⚠️ 계획서 §6의 재현 기준이 부적절했다 — 고쳤다

계획서는 "**총량으로 판정한다** — 6건쯤 흔들린다가 재현 기준"이라고 썼다. 3차에서
4건이 나왔으니 그 기준으로는 판정이 애매해진다.

**기준 자체가 틀렸다. 흔들림 개수는 재현 기준이 될 수 없다.**

- 흔들림은 확률적 사건이다. 18케이스가 각자 확률 p로 흔들린다면 흔들린 **개수**도
  확률변수다. 기대값이 5쯤이면 표준편차가 2쯤이라 **4와 6은 같은 분포에서 나오는
  정상 범위**다
- 게다가 **반복 횟수가 감지력을 바꾼다.** repeat 3은 repeat 2보다 흔들림을 더 잘
  잡는다(기회가 많다). 그런데 감지력이 더 높은 3차에서 4건이 나왔다 — 개수를
  실행 간에 나란히 비교하는 것 자체가 엄밀하지 않다

**대신 이 셋을 재현 기준으로 쓴다.**

| 기준 | 왜 |
|---|---|
| **기대 불일치 건수** | 값이 틀리는 것은 흔들림보다 안정적으로 재현된다. 실측 9·9·9 |
| **고정 실패 케이스의 존재** | `경복궁 코스 짜줘`·`경복궁 일정 짜줘`가 항상 `null`. 확률이 개입하지 않는다 |
| **flash의 0/0** | 대조군. 이것이 흔들리면 모델 스냅샷이 움직였다는 뜻이다 |

**이것이 사후 조정이 아닌 이유**: 판정 기준(§8)이 아니라 재현 기준(§6)을 고친
것이고, 원리(흔들림 개수는 확률변수다)로 정당화된다. 계획서가 임계값을 못 박지
않은 것이 설계 결함이었다.

## 3. 지연 — 세 번 일관된다

| | 2차 | 3차 | 평균 |

| `flash` 중앙값 | 2,146ms | 2,094ms | ~2,120ms |

약 +1.2초로 추정된다 — **분류 쪽은 아직 재지 않았다**(1단계에서 잰다).

## 4. 새로 드러난 것 — 앞선 판단 하나를 정정한다

**"시간 값(`time_available`)은 lite에서도 살아 있다"는 판단을 정정한다.**

1차 실행만 보고 "5시간은 살아 있으니 그 가설은 기각"이라고 적었다. 세 실행을
합쳐 보면 **회차마다 다르다.**

| 발화 | 1차 | 2차 | 3차 |
|---|---|---|---|
| `토요일 오후 2시부터 5시간 코스 짜줘` | null / 300 / 300 | **300 고정** | **null 고정** |
| `5시간 코스 짜줘` (대조군) | **300 고정** | null / 300 | 300 / null / null |

**시간 값도 날아간다.** 그것도 흔들림의 일부였고, 1차 한 번으로는 보이지 않았다.

**교훈**: 대조군이 통과했다고 본체의 가설을 기각하면 안 된다. 3차에서는 **대조군
쪽이 오히려 더 흔들렸다**(`5시간 코스 짜줘`가 300/null/null). 대조군도 같은 확률로
흔들리는 대상이면 대조군 역할을 못 한다.

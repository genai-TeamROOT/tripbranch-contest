## 1. 실행 전 확인한 것 (실 API 0호출)

**① 모델 이름이 실재한다.** 레포가 이미 안다 — `scripts/compare_gemini_audio_models.py:40`,
`tests/test_provider_settings.py:141`. 추측한 이름이 아니다(RULES 함정 49).

**② 이 모델은 `thinking_budget=0`을 받는다.** `intent_experiments_2026-08.md` §5의
모델별 표에서 **지원** 쪽에 있고, `gemini.py`의 `_REJECTS_ZERO_THINKING_BUDGET`에도
없다. **거부 쪽은 `gemini-3.5-flash-lite`와 `gemini-3.6-flash`다.**
→ 프로덕션 경로가 그대로 돌고, 함정 46의 400 사고는 이 모델에서 안 난다.

**③ 측정 데이터는 0건이다.** `test_results/` 전체를 훑었고 이 모델이 나오는 곳은
위 §5의 예산 지원 표 한 줄뿐이다. 성능·재현성 기록은 없다. **진짜 새 데이터다**
(RULES 함정 47의 사전 확인).

**④ 러너에 가드를 넣었다.** `verify_schedule_condition_extraction.py`에는 사전 거부·
연속 실패 중단·원자료 저장이 **없었다.** 54호출짜리 명령을 가드 없이 건네지 않는다.

## 2. 무엇을 재고 무엇을 안 재나

3.5-flash-lite를 기각한 것은 **정확도가 아니라 재현성**이었다(`호출부_지도.md` §6).
그래서 같은 두 자리를 같은 프로토콜로 잰다 — **비교 가능성이 이 측정의 값어치다.**

| 단계 | 무엇 | 러너 | 호출 | 왜 |
|---|---|---|---|---|
| A | 스모크 | 양쪽 각 1건 | **2** | 경로가 사는지만 |
| B | **조건 추출 재현성** (FAST) | `verify_schedule_condition_extraction.py` | **54** | 3.5-lite를 죽인 자리. 0단계와 같은 프로토콜 |
| C | **이동수단 판정** (GENERATION) | `measure_mode_judge.py` | **14** | Q2-b에서 3.5-lite를 죽인 자리 |
| D | 갈린 것만 좁혀 반복 | 조건부 | ~15 | B·C에서 갈린 것이 있을 때만 |

**B가 `--repeat 3`인 이유를 적어둔다.** 기본은 1이다(RULES 0절 14번 ④). 여기서 3을
쓰는 것은 **재는 대상이 흔들림 자체**이고, `0단계_기준선.md`가 "repeat 3은 repeat 2보다
흔들림을 더 잘 감지한다"를 이미 근거로 남겼기 때문이다. 그리고 flash·3.5-lite 기준선이
**전부 repeat 3**이라 여기서 줄이면 **비교가 성립하지 않는다.**

### 안 재는 것

| 항목 | 왜 |
|---|---|
| 분류 정확도 68건 | FAST는 스위치 하나다. 추출이 실패하면 분류 점수는 결정을 못 바꾼다(Q1에서 배운 것) |
| 편성 계약 | GENERATION 스위치가 하나다. C가 실패하면 편성은 볼 필요가 없다 |
| 답변·요약 6종 | 같은 이유 + 사람 눈 검사 비용 |
| 단가 | **모른다.** 잰 뒤에 확인한다 — 품질이 안 되면 단가는 의미가 없다 |

## 3. 판정 기준 — **실행 전에 적는다**

### B (조건 추출) — 대조는 `0단계_기준선.md`

| | flash | 3.5-lite | **3.1-lite 판정** |
|---|---|---|---|
| 흔들림 | 0/18 (여섯 실행 전부) | 4~6/18 (세 실행) | **1건이라도 나오면 FAST 후보에서 탈락** |
| 기대 불일치 | 0/18 | 9/18 (세 번 다 정확히) | 0/18이 아니면 탈락 |
| 폴백 낀 케이스 | 0/18 | 0/18 | 0이 아니면 그 실행은 무효 |

**흔들림 0을 요구하는 근거**: flash가 여섯 실행 전부 0이었다. 대조군이 완전히
결정적이면 "가끔 흔들린다"는 동급이 아니다(RULES 함정 52).

### C (이동수단 판정) — 대조는 `Q2b_이동수단판정.md`

| | flash | 3.5-lite | **3.1-lite 판정** |
|---|---|---|---|
| 무반응(없음·맑음) 규칙일치 | 6/6 (42회차 전부) | 없음/추천 3/5 | **6/6이 아니면 탈락** |
| 판정 배열 가짓수 | 3가지 (조건 세기를 따라감) | 2가지 (12조건이 한 배열) | 2가지면 조건을 안 읽는 것 — 기록한다 |
| 0.6km 상향 | 18/42 | **0/29** | 0이면 조건 반응이 없는 것 — 기록한다 |
| 재현성 | 같은 조건 3회 전부 동일 | 같은 입력에 두 답 | **갈리면 탈락** |

**"기록한다"와 "탈락"을 갈라 적었다.** 배열 가짓수와 0.6km는 기준표에 원래 없던
축이라 기각 사유로 쓰지 않는다 — 결과를 보고 기준을 만들면 사후 해석이다.

### 어느 쪽이 먼저 실패하면 나머지는?

**FAST와 GENERATION은 별개 스위치다.** B가 실패해도 C는 유효하고, 그 반대도 같다.
**둘 다 끝까지 잰다** — 이번 목적은 결정이 아니라 기록이다.

## 4. 명령

### A. 스모크 (2호출)

> 추출 쪽은 `--repeat 1`로 18케이스를 다 도는 것이 최소 단위라 스모크가 18호출이 된다.
> 대신 **이동수단 판정 1호출**로 모델 이름이 실제로 붙는지부터 본다 —
> 이름이 틀리면 여기서 죽고 54호출을 안 쓴다.

```
cd ~/Documents/tripbranch/backend
python -m scripts.measure_mode_judge \
  --models gemini-3.1-flash-lite --only "없음/일정" --repeat 1 \
  --out-dir test_results/model_tier_2026-09-08/mode_judge_31lite
```

**결과 (2026-09-09): 통과 — 모델 이름이 API에서 먹고 1,417ms에 응답했다.**

곁들여 나온 것 하나. `없음/일정`이 **5/6**(0.85km를 transit)이었다. 같은 조건에서
flash는 6/6(42회차 전부), 3.5-lite도 6/6이었다 — **3.5-lite가 맞힌 두 조건 중
하나를 3.1-lite가 틀렸다.**

**n=1이므로 판정하지 않는다**(RULES 함정 33). C를 돌려야 안다. 다만 §3의 C 기준이
"무반응 6/6이 아니면 탈락"이라 **첫 호출부터 기준에 걸린 것은 사실로 적어둔다.**

### B. 조건 추출 재현성 (54호출)

```
cd ~/Documents/tripbranch/backend
python -m scripts.verify_schedule_condition_extraction \
  --model gemini-3.1-flash-lite --repeat 3 --delay 1.0 \
  --out-dir test_results/model_tier_2026-09-08/extraction_31lite
```

`예정 호출 54건, 상한 60건`이 먼저 찍힌다. 실패가 3건 연속이면 중단한다.

### C. 이동수단 판정 (14호출)

```
cd ~/Documents/tripbranch/backend
python -m scripts.measure_mode_judge \
  --models gemini-3.1-flash-lite --repeat 1 --delay 0.5 \
  --out-dir test_results/model_tier_2026-09-08/mode_judge_31lite
```

**합계 69호출.** 3.5-lite 때 같은 두 자리에 쓴 것이 54 + 30 = 84호출이었다.

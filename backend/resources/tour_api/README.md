# TourAPI 코드 사전

TourAPI(KorService2)가 파라미터로 받는 코드값을 떠 둔 정적 자료다. 요청마다 조회
오퍼레이션을 부르지 않으려고 저장소에 넣었다.

| 파일 | 내용 |
| --- | --- |
| `tour_api_category_codes.json` | 3단계 분류체계(`lclsSystm1~3`)와 `contentTypeId` 대응 240행 |
| `tour_api_ldong_codes.json` | 법정동코드 시도 16건과 그 하위 시군구 269건 |

## 법정동코드 — 출처

- 오퍼레이션: `GET https://apis.data.go.kr/B551011/KorService2/ldongCode2`
  - `lDongRegnCd`를 비우면 시도 목록, 주면 그 시도의 시군구 목록이 온다.
- 추출일 2026-08-20. 시도 1회 + 시도별 1회씩 총 17회 호출로 만들었다.

출처를 파일 최상위 `attribution` 멤버에도 넣었다. 데이터와 출처가 떨어지면 나중에 어느
쪽이 근거인지 추적할 수 없어서다.

```json
{
  "attribution": { "...": "출처와 추출일" },
  "regions": [
    { "code": "11", "name": "서울특별시",
      "districts": [{ "code": "110", "name": "종로구" }] }
  ]
}
```

`code`가 각각 `lDongRegnCd`, `lDongSignguCd`에 그대로 들어간다. 종로구는
`11` / `110`이고, 이 값이 `app/place_search_policy.py`에 상수로 박혀 있다.

## 왜 행정표준코드 파일로 대신하지 않는가

법정동코드는 행정표준코드관리시스템에서 전체자료를 내려받을 수 있고, 대부분의 시군구는
그 10자리 코드의 앞 5자리를 2자리(시도) + 3자리(시군구)로 쪼갠 값과 일치한다. 그런데
TourAPI 응답은 그 규칙에서 네 군데 벗어난다. 규칙으로 유추하지 말고 이 파일을 본다.

- **세종특별자치시는 시도 코드가 `36110`으로 5자리다.** 시군구가 없는 단층제라 시도 자리에
  앞 5자리가 통째로 들어간다. 하위 시군구도 자기 자신 1건(`36110`)뿐이다.
- **시도가 17개가 아니라 16개다.** 광주광역시(`29`)와 전라남도(`46`)가 없고
  `12 전남광주통합특별시` 하나로 합쳐져 있다.
- **통합 시도의 시군구 코드는 재배치됐다.** 광주 동구는 행정표준코드 기준 `29` / `110`이지만
  여기서는 `12` / `210`이다. 옛 코드로 조회하면 맞지 않는다.
- **경기도 목록은 시와 그 아래 일반구가 같은 레벨에 섞여 있다.** `110 수원시`와
  `111 수원시 장안구`가 나란히 있어서 서로 포함관계다. 시 코드로 조회하면 구 단위 결과를
  전부 포함하므로, 둘을 합산하면 중복된다.

화성시 만세구·효행구·병점구·동탄구처럼 최근 개편도 반영돼 있다. 행정구역이 개편되면 위
오퍼레이션을 다시 호출해 이 파일을 갱신한다.

## 코드가 유효한 것과 데이터가 있는 것은 다르다

이 파일은 "TourAPI가 받아주는 코드"까지만 보장한다. 그 지역에 실제로 콘텐츠가 있는지는
`areaBasedList2`를 `numOfRows=1`로 호출해 `totalCount`를 보고 판단해야 한다. 코드가
유효해도 결과가 0건일 수 있다.

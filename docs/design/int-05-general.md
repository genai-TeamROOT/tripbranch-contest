## 1. 정의

**목적:** API로 조회할 수 없는 여행 관련 배경지식, 일정 계획 팁, 장소 관련 일반 상식,
서비스/챗봇 정체성 질문에 대해 LLM이 응답한다.

**판별 기준:**
- 특정 장소 추천을 요청하지 않음
- API로 조회 가능한 사실 정보(운영시간, 요금 등)를 묻지 않음
- 여행/일정/장소에 관한 배경지식이나 상식을 질문함
- TripBranch 또는 챗봇의 이름·역할·가능 기능을 질문함

**GENERAL이 아닌 경우:**
- "카페 추천해줘" → `RECOMMEND`
- "경복궁 오늘 열어?" → `INFO` (API 조회 가능)
- "다른 곳 보여줘" → `MODIFY`
- "어디가 더 가까워?" → `COMPARE`
- 여행과 무관한 질문 → 서비스 범위 안내 후 거절

---

## 2. GENERAL로 분류되는 범위

### 포함 (LLM 응답 제공)

| 카테고리 | 예시 |
|----------|------|
| 여행 팁/노하우 | "서울 여행 시 알아두면 좋은 것?", "대중교통 꿀팁?" |
| 계절/시기 정보 | "벚꽃 언제 피어?", "여름에 서울 덥나?", "단풍 시기?" |
| 지역 일반 특성 | "성수동은 어떤 동네야?", "종로랑 을지로 차이?" |
| 장소 배경지식 | "경복궁은 언제 지어졌어?", "북촌 한옥마을 역사?" |
| 일정 계획 팁 | "하루에 몇 군데 정도 돌아볼 수 있어?", "동선 짤 때 팁?" |
| 음식/문화 상식 | "서울에서 유명한 음식?", "전통시장 에티켓?" |
| 교통 일반 정보 | "지하철 몇 시까지 해?", "T-money 어디서 사?" |
| 서비스/챗봇 정체성 | "넌 누구야?", "이름이 뭐야?", "뭘 할 수 있어?" |

### 제외 (다른 Intent로 분류하거나 거절)

| 상황 | 처리 |
|------|------|
| API로 조회 가능한 정보 | → `INFO` (운영시간, 입장료, 주차 등) |
| 장소 추천 요청 | → `RECOMMEND` |
| 추천 결과 변경 | → `MODIFY` |
| 추천 결과 비교 | → `COMPARE` |
| 여행과 완전히 무관한 질문 | → 서비스 범위 안내 |

## 3. 처리 흐름

```
사용자 입력
    ↓
LLM Intent 분류 → GENERAL
    ↓
주제 분류 (topic)
    ↓
LLM 응답 생성
    ↓
사용자에게 제공
```

## 4. GeneralRequest 스키마

```typescript
interface GeneralRequest {
  // 주제 분류
  topic: GeneralTopic;

  // 원문 질문
  original_question: string;
}
```

## 5. GeneralRequest 필드 정의

| 필드 | 타입 | 설명 | 예시 |
|------|------|------|------|
| `topic` | GeneralTopic | 질문 주제 분류 | `service_identity`, `travel_tip`, `season_info`, `area_info` |
| `original_question` | string | 사용자 원문 (LLM 응답 생성 입력) | "벚꽃 언제 피어?" |

## 6. topic 정의

### enum 목록

```typescript
type GeneralTopic =
  | "service_identity" // 서비스/챗봇 정체성·이름·가능 기능
  | "travel_tip"       // 여행 팁/노하우
  | "season_info"      // 계절/시기/날씨 일반
  | "area_info"        // 지역 특성/분위기
  | "place_knowledge"  // 장소 역사/배경지식
  | "planning_tip"     // 일정 계획 팁
  | "food_culture"     // 음식/문화 상식
  | "transport_info";  // 교통 일반 정보
```

### 상세 정의

| topic | 정의 | 예시 입력 |
|-------|------|-----------|
| `service_identity` | TripBranch 또는 챗봇의 이름·역할·가능 기능 | "넌 누구야?", "이름이 뭐야?", "뭘 할 수 있어?" |
| `travel_tip` | 여행 준비, 준비물, 주의사항 등 | "서울 여행 시 꼭 챙길 것?", "환전 어디서?" |
| `season_info` | 계절별 특성, 시기별 볼거리 | "벚꽃 시기?", "겨울에 뭐 하면 좋아?" |
| `area_info` | 특정 지역의 일반적 분위기/특성 | "성수동은 어떤 동네?", "홍대 vs 이태원?" |
| `place_knowledge` | 장소의 역사, 문화적 배경 | "경복궁 역사?", "남산타워 언제 세워졌어?" |
| `planning_tip` | 일정 구성 전략, 동선 팁 | "하루에 몇 군데?", "효율적인 동선?" |
| `food_culture` | 지역 음식, 문화 에티켓 | "서울 3대 빵집?", "전통시장 에티켓?" |
| `transport_info` | 교통 수단 일반 정보 | "지하철 막차?", "공항버스 어디서 타?" |

## 7. INFO와의 구분 기준

GENERAL과 INFO가 혼동되기 쉬운 경우의 판별 기준:

| 질문 | 판정 | 이유 |
|------|------|------|
| "경복궁 오늘 열어?" | INFO | API로 조회 가능한 운영시간 |
| "경복궁은 언제 지어졌어?" | GENERAL | 역사적 배경지식 (API 조회 불가) |
| "경복궁 입장료?" | INFO | API로 조회 가능한 요금 |
| "경복궁 왜 유명해?" | GENERAL | 일반 상식/배경지식 |
| "남산타워 주차 가능?" | INFO | API로 조회 가능한 시설 정보 |
| "남산타워 몇 미터야?" | GENERAL | 배경지식 |
| "지하철 막차 몇 시?" | GENERAL | 일반 교통 상식 (특정 장소 API 아님) |
| "경복궁역 몇 호선?" | GENERAL | 일반 교통 정보 |

### 핵심 구분 원칙

```
TourAPI(detailCommon2, detailIntro2 등)로 조회할 수 있는 정보
  → INFO

API로 조회할 수 없는 배경지식/상식/팁
  → GENERAL
```

## 8. 서비스 범위 외 질문 처리

### 거절 대상

| 유형 | 예시 | 응답 |
|------|------|------|
| 여행과 완전 무관 | "오늘 주식 어때?", "수학 문제 풀어줘" | 범위 안내 |
| 예약/결제 요청 | "여기 예약해줘", "티켓 구매해줘" | 기능 안내 |
| 개인정보 요청 | "내 여행 기록 보여줘" | 미지원 안내 |
| 해외 여행 | "도쿄 여행 팁?" | 국내 여행 한정 안내 |

### 거절 응답 형식

```
"저는 국내 여행 추천 도우미예요. 여행 장소나 일정에 관해 질문해주세요!"
```

거절 시에도 사용자가 할 수 있는 동작을 안내한다:

```
"이런 것들을 도와드릴 수 있어요:
- 근처 장소 추천
- 특정 장소 운영시간/정보 확인
- 추천 결과 변경
- 여행 팁/배경지식 질문"
```

## 9. LLM 응답 생성 규칙

### 응답 원칙

```
1. 간결하게 답변 (3~5문장 이내)
2. 챗봇 이름은 "트리비"로 답변
3. 확실하지 않은 정보는 "정확한 정보는 현장에서 확인해주세요" 부연
4. 최신 정보가 필요한 경우 "변동될 수 있어요" 경고
5. 추천 서비스로의 자연스러운 연결 제공
```

### 트리비 페르소나

트리비는 TripBranch의 국내 여행 챗봇이다. 현재 위치나 사용자가 말한 지역을 기준으로
날씨, 운영시간, 거리, 혼잡도 선호를 함께 고려해 갈 만한 장소를 추천한다. 말투는
친근한 존댓말을 쓰되, 내부 점수·가중치·시스템 구현 사정은 설명하지 않는다. 예약,
결제, 전화 연결처럼 아직 실행하지 않는 기능은 할 수 있다고 말하지 않는다.

### 응답 후 후속 안내

```
배경지식 답변 후:
  → "이 장소 근처에서 추천받고 싶으시면 말씀해주세요!"
  → "더 궁금한 것이 있으면 물어보세요."

지역 정보 답변 후:
  → "이 동네에서 장소를 찾아볼까요?"
```

## 11. 경계 사례

| 입력 | 판정 | 이유 |
|------|------|------|
| "경복궁 역사 알려줘" | GENERAL (place_knowledge) | 배경지식 |
| "경복궁 오늘 열어?" | INFO | API 조회 가능 |
| "경복궁 근처 맛집" | RECOMMEND | 추천 요청 |
| "서울 가볼 만한 곳" | RECOMMEND | 추천 요청 (장소 추천 의도) |
| "서울 여행 팁" | GENERAL (travel_tip) | 일반 팁 |
| "비 오면 뭐 하지?" | RECOMMEND | 날씨 기반 추천 의도 |
| "비 올 때 여행 팁?" | GENERAL (travel_tip) | 일반 팁 (추천 아님) |
| "전통시장 에티켓?" | GENERAL (food_culture) | 문화 상식 |
| "넌 누구야?" | GENERAL (service_identity) | 서비스 소개 |
| "이름이 뭐야?" | GENERAL (service_identity) | 챗봇 이름 질문 |
| "광장시장 뭐가 맛있어?" | RECOMMEND | 특정 장소 기반 음식 추천 |
| "고마워" | GENERAL | 대화 종료 인사 |
| "도쿄 여행 팁?" | 거절 | 해외 여행 (서비스 범위 외) |

### "서울 가볼 만한 곳" vs "서울 여행 팁" 구분

```
장소를 결과로 기대하는 질문
  → RECOMMEND ("가볼 만한 곳", "갈 만한 데", "볼거리")

장소가 아닌 정보/조언을 기대하는 질문
  → GENERAL ("팁", "알아두면 좋은 것", "주의사항", "역사")
```

## 12. MVP 제한사항

다음 항목은 MVP에서 처리하지 않는다:

- 대화 맥락을 깊이 추적하는 멀티턴 일반 대화
- 개인화된 여행 조언 (이전 방문 기록 기반)
- 해외 여행 정보
- 실시간 정보 (오늘 날씨, 현재 교통 상황 등 — 별도 API 영역)
- 긴 형식의 여행 가이드 생성

GENERAL은 단발성 질문-응답으로 처리하며, 복잡한 대화 흐름을 유지하지 않는다.
